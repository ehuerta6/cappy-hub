## Status terms

- **Shipped** means the capability is implemented on the inspected repository `main`; it does not prove production deployment.
- **Historical** means the workflow is retired or superseded; retained rows and audit evidence do not make it active.
- **Operationally unverified** means repository evidence does not establish whether an external integration is configured or healthy in production.

## Slice-boundary decisions

- Identity and access is separate from the Officer directory/profile: access and Branch-scope rules cross many workflows, while Officer management owns the durable record and its lifecycle.
- Event management is separate from Event participation: Event CRUD/lifecycle and the Officer signup/Time Slot-to-Point flow have different actors and entry paths, but remain linked because the roster and schedule determine eligible awards.
- Points stays a separate slice because Event and Task workflows produce source-derived awards while administrators also create independent signed transactions and corrections.
- Administrative catalogs and academic periods have distinct context: catalogs govern reusable classifications and assignment choices, while periods are date ranges that select historical/current/future views across existing records.
- Internal Calendar and Google Calendar are separate: one is a read-only Cappy Hub projection; the other performs a one-way external Event mirror with recovery and operational credentials.
- Dashboard is documented as its own user-facing summary slice, but its data and actions remain owned by Events, Tasks, Points, and period views.
- Waitlist and Presenter Slot history share one historical Event slice because neither is an active workflow and both exist only as retired Event-side records/contracts. The System Log UI is grouped with audit provenance instead, because audit remains a cross-cutting data capability.
- Signup Sheet URLs and Task-to-Event links stay inside their owning Event/Task slices; the current contracts provide no independent synchronization or mutation workflow for either relationship.

## Cross-slice relationships

- Event schedule, confirmed signup, and optional Time Slot assignments feed eligible source-derived Event Points; correction and Delete/Restore preserve distinct transaction history.
- Task assignment completion and due-date eligibility feed source-derived Task Points. A Task's optional Event link does not make its award depend on Event changes.
- Officer identity, lifecycle, Position, Branch membership, and application role inform access; they remain separate attributes and preserve historical relationships.
- Recurring series create real occurrence records and coordinate Event/Task lifecycle changes without collapsing occurrence identity.
- The internal Calendar reads Event and Task dates. The external Google Calendar is a separate one-way Event mirror; neither becomes a second Cappy Hub source of truth.
- Dashboard values summarize the owning workflows and do not create independent records or permissions.
- Event, Task, Point, and Warning changes may create personal notifications; notification delivery, audience, and review state remain separate from the underlying business record's authority.
