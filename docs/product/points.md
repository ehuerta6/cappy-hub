# Points

## Points

### Current / shipped

Point transactions are signed amounts, and an Officer's total is the sum of active transactions (`removed_at` is null). The supported types are participation, task, manual, and correction. Transactions may link to an Event or Task as appropriate and retain actor attribution. Event participation and Task completion awards are processed by trusted database workflows. Manual transactions and corrections are independent signed credit with a nonblank reason and optional Event reference. Multiple intentional manual entries may share an Officer/Event pair and coexist with automatic participation in either creation order. Automatic ordinary Event and Officer/slot identities remain unique; manual entries do not reset processing or restore removed awards. Admins may create manual transactions/corrections, edit transaction amounts where currently authorized, and logically remove transactions. The Points page explains the fixed participation rule; retained legacy rate configuration does not control new awards.

Logical removal excludes a transaction from totals while preserving its row and history. Removing an automatic award does not cause its processor to recreate it. A correction is a separate signed transaction and does not erase the original. Schedule/duration corrections reconcile source-derived participation, including replacing directly edited automatic amounts; descriptive edits leave awards unchanged. If an active legacy participation transaction lacks the newer basis metadata, a source correction may recalculate it and record that its original schedule basis is unknown; the correction establishes current basis without fabricating historical evidence. Intentional removals remain excluded. An Admin can confirm a verified premature removal with a reason, preserving the old removed transaction and linking one legitimate replacement after corrected eligibility. Point History search covers Officer, reason, Event, and Task; the visible filters are award type and, for Admins, Active, Removed, or All history. Admins see actor/removal information; other Officers see active history. History is paginated eight rows at a time, and existing filtered links retain their URL context.

The Points page shows the fixed participation rule, selected-period Officer ranking, authorized transaction controls, lifetime totals through profiles, and Point History. Period ranking includes active Officers only and uses their signed active transactions attributed by Event date, Task due date, or transaction creation date for unlinked Points. The Dashboard shows the signed-in Officer's lifetime total, current-period net Points, and the latest five active transactions.
