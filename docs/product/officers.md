# Officers

## Officers

### Current / shipped

Admins create and edit Officer profiles, manage application roles through the access workflow, and can deactivate or reactivate Officers. Profiles expose Officer identity, Position, Branches, status, associated Event participation (with Volunteer/Attend badges), associated Tasks (with `Complete`, `Pending approval`, `Overdue`, `Upcoming`, and `No longer needed` status badges), selected-period **Task completion** and **Recorded events** summary cards, warnings according to visibility rules, total Points, and Point history (with a period-scoped CSV export). The directory supports name/email search, status, Position, and Branch filters, a **3+ warnings** quick view for authorized reviewers, one-click **Copy UTEP emails** (UTEP emails only, excluding personal email), and an Admin-only **Export CSV** download matching the current filters and ordering across all pages with the four documented columns (`Name, Email, Classification, Position`, using UTEP email only and excluding personal email addresses).

All active Officers can switch to the **Activity** view (`/officers?view=activity`) to compare Officer activity across the selected Academic Period (defaulting to the current period) without combining Tasks and Events into a single blended score:

- **Task completion %** is approved completions on due Tasks (`due_date < today` in America/Denver) divided by due Tasks within the selected period. Upcoming Tasks, `No longer needed` Tasks, and removed Tasks are excluded from the denominator; pending-approval completions are tracked separately and excluded from the numerator until approved. When an Officer has no due Tasks in the period, the view shows **No Tasks due** instead of `0%`.
- **Recorded events** counts distinct non-deleted, non-cancelled Event occurrences once per Officer, combining both `Volunteer` and `Attend` signups while displaying each breakdown alongside the total. Time Slot signups on the same occurrence count as one Event. This metric is explicitly labeled as recorded signups rather than verified attendance.
- The **Activity** view includes quick follow-up filters (**All**, **Incomplete due Tasks**, **Pending approval**, **0 events**), sorting (**Name**, **Task %**, **Recorded events**), contextual **Copy filtered emails** (UTEP emails only), and **Export activity CSV** (available to any active Officer, honoring directory filters and selected period, and excluding personal email).

Deactivation preserves the Officer row, authentication link, and Event, Task, Warning, Point, and audit references, including existing Event signups. It is a lifecycle change, not routine hard deletion. Inactive Officers cannot access protected workflows or be newly signed up, assigned, or selected as a manual Point recipient through trusted mutations. The Officers directory defaults to Active and offers explicit Active, Inactive, and All views; routine Point totals and new recipient selectors include only active Officers. Point history and Officer profiles remain available for historical records. Position, Branches, and application role are not implicitly changed by deactivation or reactivation.

Position authorization uses stable, non-null machine codes only for the six required Positions: President, Vice President of Operations, Vice President of Academics, Secretary, Lead, and Officer. These codes are independent of display names, and the required Positions cannot be renamed, deleted, or retired. Every Position has a stable database ID; custom Positions intentionally retain `code = NULL`, so changing or copying a display name cannot grant system privileges. Admins may create and rename custom Positions and use reversible Delete/Restore, including when historical records reference them. Branches use the same recoverable CRUD. Delete preserves catalog IDs and dependent records; previously retired values remain unavailable and recoverable from Deleted values. Retired Branches and custom Positions remain readable through existing relationships but cannot be newly assigned. An existing relationship can remain during an unrelated edit or be removed.
