# Events and participation

## Events

### Current / shipped

An Event occurrence can be created, viewed, and edited within the caller's trusted management scope. Active Leads may create and edit Events across all Branches, including global Events. Notification settings saved with an Event edit, recurrence edits, and current roster/signup and Time Slot management follow that scope where those workflows already permit them; other Event administration and historical corrections retain their existing authorization. Events use a catalog Event Type. Current available types include Meeting, Social, Workshop, and **Session**; historical types may remain readable without being offered for new Events. An Event Type is classification, not a separate workflow.

Events have an America/Denver local date and wall-clock schedule, a reusable location value, zero or more Branches, and zero or more external resource links with readable labels. Common labels include Slides, Meeting notes, Signup sheet, and Documentation; managers may enter custom labels. Existing Slides, Meeting notes, and Signup sheet values remain editable as resource links. A Signup sheet is an **external resource URL only**. Native Cappy Hub Event signup is the authoritative roster. No Sheet rows are imported, exported, synchronized, counted as participation, or used to award Points.

Officers sign themselves up or leave through the native signup workflow while signup is open. Each occurrence may have a positive Max volunteers limit; blank means unlimited. The confirmed participation roster remains `event_officers`. A full Event rejects additional signups; removing a confirmed signup or changing capacity never promotes anyone. Authorized managers may still edit a past Event's capacity within the existing management workflow; that edit does not change the historical confirmed roster or awards. Actual historical participation changes use the existing Point correction workflow. Only confirmed Officers qualify for participation Points. Authorized managers can add or remove multiple active Officers in bulk. Events with no Branches are global; active Leads may create and edit them, while other Event administration retains its existing authorization.

Events may optionally contain occurrence-owned Time Slots. Managers can use equal or custom intervals; gaps and overlaps are allowed, and each slot may have its own optional positive capacity. A slotted Event uses per-slot capacities only; its Event-wide Max volunteers limit is hidden and stored as null. Events without Time Slots retain the optional Event-wide Max volunteers limit. Slots may be enabled on a new Event or an existing Event with no confirmed signups; they cannot be enabled after signups exist. No signup or historical Point record is migrated to enable slots. Session Events remain valid Event Types but cannot contain volunteer Time Slots. Existing historical presentation rows do not enable an active Presenter workflow. Event schedule edits that would put a slot outside the new Event bounds fail without changing either schedule or slots. Schedule edits may create overlaps among already-assigned slots and preserve those assignments. New self-service, manager-added, or corrected assignments cannot assign one Officer to overlapping slots in the same Event occurrence. Existing slot identities remain stable during schedule edits; new slots are created independently, and signup or Point history is never transferred to another slot. Removing a slot with registrations or Point history is rejected, and a slot with Point history cannot be rescheduled. Recurring Event copies preserve each occurrence's slot correspondence. Officers can select one or more slots, all slots atomically, leave one, or leave all; the last selection also removes the canonical Event signup. Per-slot capacities and ordinary Event-wide capacities are enforced by trusted database mutations that serialize concurrent changes. Authenticated Officers can see the names registered for each slot under the existing Event roster visibility rules. Managers can correct slot assignments within their existing Event permissions.

Schedule determines whether an Event is upcoming, happening, or past. New Event administration uses reversible Delete and Restore for one occurrence. Delete excludes every linked Point transaction from active totals while preserving the Event, signups, Volunteer Time Slots, relationships, recurrence identity, and audit history. Restore reactivates only Points suspended by that Delete and reconciles eligible participation without reviving independently removed awards. Deleted Events have a manager-scoped Deleted view and stay out of routine lists, Dashboard, Calendar, and new operations. Historical cancelled Events retain their cancelled state and existing cancellation-restoration behavior. Historical archive rows remain identifiable and recoverable; migration does not reinterpret their Point activity.

The Events page defaults to current non-cancelled Events and can show Upcoming, Happening, Past, Cancelled, or (for authorized managers) Deleted groups. Historical archived Events remain discoverable in Deleted and retain their archive label. Events are organized around the signed-in Officer's own signups and other Events; signups are offered only while the Event permits them. The Dashboard and Calendar omit cancelled and deleted Events.

Under [Issue #402](https://github.com/ehuerta6/cappy-hub/issues/402), each Event signup is either Volunteer or Attend. Self-service signup presents two explicit actions, **Sign Up** (Volunteer, 2 Points/hour) and **Attend** (1 Point/hour); submitting either selects exactly one type, and an existing signup can switch between them. Time Slot signups are Volunteers. When a non-cancelled, active timed Event ends, trusted processing awards Volunteers 2 Points and Attendees 1 Point per eligible hour; every current signup receives its selected award without attendance validation. An Event without Time Slots retains one full-schedule participation transaction per signup. On a slotted Event, each selected Volunteer/slot pair receives its slot's fractional duration; gaps earn no Points. Historical configured and snapshotted rates remain evidence, and changing the new rates does not reprice existing Event awards. Relevant schedule/duration corrections retain the source-derived reconciliation rules, replacing a directly edited automatic amount when its schedule changes; moving an Event into the future mechanically excludes its participation until the corrected end, retaining signups and audit history. Descriptive edits do not recalculate credit. Independent manual credit, corrections and intentional removals are preserved.

### Historical Presenter Slot records

Active Presenter Slot workflows are retired. Session Events remain valid and use ordinary Event signup and participation behavior. Historical presentation rows remain readable on the Event detail page, including their assigned Officer, order, topic, resource link, difficulty, and preparation notes. Their stable IDs and audit evidence remain intact. Event signups, Officer deactivation, valid Event edits, Event Type edits, and Volunteer Time Slot behavior do not mutate or depend on the historical Presenter Slot rows. Presenter Slot creation, ordering, assignment, claiming, stepping down, removal, and detail editing are unavailable.
