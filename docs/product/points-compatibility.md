## Distinguishing invalid premature credit from intentional suppression

The two cases cannot reliably be classified by current row shape. A schedule correction proves the source changed; it does not prove why an Admin removed an award or whether a legitimate suppression should carry into a later eligibility basis. Missing audit/actor data must remain an explicit unknown.

| Evidence class                                                                  | Safe constraint for subsequent reconciliation                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirmed invalid premature award tied to a superseded schedule basis           | Preserve original transaction/removal/actor history. Exclude it before corrected end. After corrected end, issue/reconcile legitimate credit using retained eligible signups, with explicit linkage to the superseded basis rather than erasing the prior removal. Event 53 is the reported example, not an ID-specific exception. |
| Confirmed deliberate suppression of otherwise legitimate participation          | Keep suppressed. Event restore or routine recalculation must not reactivate it indiscriminately.                                                                                                                                                                                                                                   |
| Mechanical slot-selection removal with existing structured provenance           | Apply existing scoped selection behavior; do not reinterpret as Admin intent or Event lifecycle suspension.                                                                                                                                                                                                                        |
| Removal with unknown or conflicting intent, provenance, schedule basis or actor | Preserve excluded state and history. Require reviewed compatibility handling and, when necessary, authorized maintainer confirmation before changing credit. Chronology alone is insufficient.                                                                                                                                     |
| Directly edited automatic amount                                                | Preserve edit evidence; relevant source corrections apply the source-derived amount with before/after audit, while unrelated descriptive edits do not recalculate.                                                                                                                                                                 |

The approved reconciliation behavior for corrected Event schedules was implemented in [PR #343](https://github.com/ehuerta6/cappy-hub/pull/343). Current Points and Event contracts describe the shipped behavior, including preserving intentional removals and historical transaction/audit records. The old fixture gap and pre-implementation assertions are no longer current guidance.

It calls no business functions. **Do not run it against production without separate explicit authorization.** It has no connection credentials or hosted execution helper.

An authorized operator must first confirm the inspected schema matches the repository migration milestone and that the session can see all relevant rows (application RLS-limited counts cannot establish global absence). Use an independently restricted read-only connection. Keep credentials outside logs and command history. Do not relax RLS or grant new app privileges for evidence collection. If a limit is hit or access is incomplete, report partial evidence instead of increasing load or claiming absence. Outputs contain only allowed categories, numeric rates/counts/totals and booleans; review small sensitive groups before sharing, and never export raw identities, reasons or audit JSON into this repository.
