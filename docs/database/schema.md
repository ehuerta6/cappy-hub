# Database schema overview

This is a concise orientation to selected public entities and invariants, not an exhaustive column catalog. The current migration chain defines the database contract; [`lib/database.types.ts`](../../lib/database.types.ts) supplies generated application-facing shapes and relationship metadata. Read the named migrations for exact DDL, indexes, grants, policies, and function behavior.

## Views and access boundaries

Generated public views include `dashboard_summary`, `officer_point_totals`, and `point_history`. `academic_period_context` and `academic_period_point_summary` are generated function entries, not views. Inspect their migration definitions and entries in [`database.types.ts`](../../lib/database.types.ts) before relying on columns or filtering semantics.

RLS is enabled on protected public tables. The baseline client model grants authenticated reads through policies and withholds direct table writes; approved mutations use trusted database functions. The base active-Officer read rules and function grants are in [final RLS](../../supabase/migrations/20260928140107_final_rls.sql). Later migrations add entity-specific policies—for example, Warning visibility, slot rosters, academic periods, and Calendar sync failures—so consult each linked migration rather than assuming one policy applies to all entities. Private-schema tables/functions support internal processing and are not listed as application-facing public entities.
